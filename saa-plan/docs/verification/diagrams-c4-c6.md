# Course diagrams c4, c5, c6: sources

Written 2026-10-16 for `site/diagrams/c4.js` (Designing a Containerized Architecture, labs l4a–l4d), `site/diagrams/c5.js` (Designing a Compliant, Secure, and Governed Architecture, labs l5a, l5b) and `site/diagrams/c6.js` (Designing a Hybrid Architecture, labs l6a, l6b).

## How it was done

- **What each diagram draws** follows the course's lesson names in plan.js, its `STEP_TAGS` and the key points in `site/keys/c4.js`, `c5.js`, `c6.js`. Nothing is drawn that those do not cover. Left out on purpose: IAM Identity Center (in no c5 key point and no c5 `STEP_TAGS`), EKS as a box (c4 covers it as one comparison point only), Global Accelerator, Route 53 routing and ARC as boxes (c4d, c4e: they are points in the parts instead), AWS DMS and Outposts (c6d; the diagram is about connecting the networks), and every Snow device (closed to new customers).
- **Most facts are reused** from the key points, whose sentences were checked against fetched AWS pages on 2026-10-12/13 (logs: `keys-c3-c4.md`, `keys-c5-c6-r1.md`). They are cited below as "keys c4b k3" (file `site/keys/c4.js`, entry `c4b`, third point; `trap` and `why` likewise). The page behind each is in those logs.
- **New facts** come from 10 web searches restricted to docs.aws.amazon.com and aws.amazon.com. aws.amazon.com and docs.aws.amazon.com cannot be fetched in this sandbox, so these were read from the search results' snippets of the official page, not from the fetched page. Each is listed with the page it came from. The ones whose exact wording the writer could not see were checked again: see "Review".
- **Framing sentences** (what would go wrong without the thing, a design reading of a fact) have no source by nature and are listed under "Inferences".
- Checks run: `node --check` on the three files, `node --test` (47 of 47 pass, including the two diagram tests), and each diagram rendered with `tools/diagram-preview.mjs` in light and dark and looked at. A scratch script also checked that no link crosses a box or an area label and that no link label is crossed by a line or an area border (only the intended overlap remains: the peering box in c6 sits across the borders of the two VPCs it joins).
- No new `DOCS` keys.

## Inferences: not a statement on a page

- Every part's opening sentence that describes the problem (for example "Containers come and go, and their output goes with them"): framing.
- c4 alb why ("the addresses behind the application keep changing"): consequence of each task getting its own network interface.
- c4 task-b why ("the tasks in the other zone keep serving"): consequence of the spread rule. Trap first sentence ("Running more tasks does not by itself protect against losing a zone"): framing.
- c4 svc trap last clause ("that second layer is gone"): from "with Fargate you manage no servers".
- c4 replica why ("a standby that only waits is wasted"): framing.
- c5 org k3 "apart from the workloads"; c5 logs k3 "does not meet a rule that nobody may delete the logs"; c5 logs trap "does not stop it".
- c6 router why first sentence; c6 dxloc why first sentence; c6 tgw k1 "attach to it once"; c6 datasync k3 "leaves room on the link for other traffic".
- Links that show one flow for many (only task A draws SQL, only task B the cache, ECR and logs): a drawing choice; both tasks do all of it.

## Review

Fact-check of the writer's five Unsure items, 2026-10-16, in the cloud sandbox. WebFetch to docs.aws.amazon.com fails here (DNS), so each verdict rests on the WebSearch summary of the official page (results limited to docs.aws.amazon.com), not on a fetched page. Quoted text is what the summary quoted from the page; "summary" marks a paraphrase.

- c4 task-b (that the zones Fargate spreads over are the zones of the service's subnets): **softened**. Two searches found no AWS docs page that says it (the summary: the results "don't explicitly say that subnets define the Availability Zones available to Fargate tasks"). Kept what the pages say: Fargate spreads tasks across accessible Availability Zones (https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task-placement.html), and the Reliability Pillar says to create subnets in different Availability Zones and choose those subnets when you create the ECS service (https://docs.aws.amazon.com/wellarchitected/latest/reliability-pillar/rel_fault_isolation_multiaz_region_system.html, summary). Changed: why "The service spreads its tasks across the zones of the subnets you give it" → "Fargate spreads a service's tasks across zones"; k1 second sentence → "AWS's reliability guidance: create subnets in several zones and choose them for the service."; trap → "Running more tasks does not by itself protect against losing a zone. Choose subnets in several Availability Zones for the service, as AWS's reliability guidance says."
- c5 tower k3 (landing zone 4.0 names): **confirmed**, no change. https://docs.aws.amazon.com/controltower/latest/userguide/special-accounts.html (now titled "Service integration accounts"): the Log Archive account is now the CloudTrail administrator account and the Audit account the Config aggregator account; the default display names are "CloudTrail Administrator" and "Aggregator account", and the names can be customized at setup (summary). https://docs.aws.amazon.com/controltower/latest/userguide/config-updates-v4.html: from 4.0 the CloudTrail administrator account's bucket holds only CloudTrail logs, and AWS Config logs go to a bucket in the Config aggregator account (summary). At the merge, q06-020 came off the "Not stated on a page either way" list in `docs/questions.md`.
- c5 shub k1 (services the Security Tooling account administers): **confirmed**, no change. https://docs.aws.amazon.com/prescriptive-guidance/latest/security-reference-architecture/security-tooling.html: the AWS Security Reference Architecture makes the Security Tooling account the delegated administrator for Firewall Manager, GuardDuty, Macie, Security Hub and Inspector (summary). Detective, which the writer's snippet also named, is not in k1, which says "such as".
- c5 gd k1 (GuardDuty for new member accounts automatically): **confirmed**, no change. https://docs.aws.amazon.com/guardduty/latest/ug/set-guardduty-auto-enable-preferences.html: the delegated GuardDuty administrator sets auto-enable to NEW (accounts that join the organization later), ALL or NONE, per Region (summary).
- c6 filegw k1 (hypervisors; cache first, S3 asynchronously): **confirmed**, no change. Hypervisors: https://docs.aws.amazon.com/filegateway/latest/files3/Requirements.html lists VMware ESXi, Microsoft Hyper-V, Linux KVM and Nutanix AHV (which uses the KVM image), and a hardware appliance ordered from a reseller (summary). Cache: https://docs.aws.amazon.com/whitepapers/latest/file-gateway-hybrid-cloud-storage-architectures/readwrite-operations-and-local-cache.html: "When a file is written to the file gateway over NFS/SMB, the gateway first commits the write to the local cache. At this point, the write success is acknowledged to the local NFS/SMB client"; the file then goes to S3 asynchronously (summary).
