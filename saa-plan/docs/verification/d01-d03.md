## Changed questions

Format: id, what was wrong, source.

- **q01-031** (explanations for the Lambda option and the key). "Lambda functions can run for at most 15 minutes" is no longer complete: functions on Lambda Managed Instances allow up to 5,400 s (90 min) for asynchronous and event-source-mapping invocations. Reworded; a two-hour job still exceeds both limits, so the key stands. https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html
- **q01-034** (explanation for the Lambda option). Same 15-minute absolute, and "no access to the operating system" was too broad now that Lambda MicroVMs exist as a separate primitive. Reworded to what holds for a Lambda function: no kernel modules or host agents, time-limited invocations. https://aws.amazon.com/lambda/faqs/
- **q01-035** (explanation for the keyed 15-minute option). Added that the 15-minute maximum belongs to the default configuration named in the stem and that Managed Instances allow up to 90 minutes. https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html
- **q01-032** (explanation for the Beanstalk option). Elastic Beanstalk now has a Cluster mode that runs on Amazon EKS, so "does not understand Kubernetes" read as wrong. It still deploys from a container image or source plus Beanstalk configuration, not from Kubernetes manifests; reworded to say that. https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/Welcome.html and https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/concepts-cluster.html
- **q02-035** (explanation for the Direct Connect gateway option). "Does not route traffic between the VPCs associated with it" has a documented exception (a supernet advertised over the same virtual interface). Reworded to "not a hub for routing between VPCs", plus the scenario fact that the company uses VPN, not Direct Connect. https://docs.aws.amazon.com/directconnect/latest/UserGuide/direct-connect-gateways-intro.html
- **q03-001** (explanation for the key). Claimed that 30 days is the minimum object age for a lifecycle transition to an IA class. The lifecycle constraints section no longer lists that rule, and the API reference says `Days` "can be 0 or any positive integer". Replaced with the AWS guidance that Standard-IA suits data kept at least a month and read once every month or two. https://docs.aws.amazon.com/AmazonS3/latest/userguide/lifecycle-transition-general-considerations.html, https://docs.aws.amazon.com/AmazonS3/latest/API/API_Transition.html, https://aws.amazon.com/s3/faqs/
- **q03-020** (explanation for the FSx for Windows option). Said it does not fit Linux instances; the FSx for Windows FAQ states it is accessible from Linux over SMB. The deciding reason is that its storage capacity is provisioned and only increased by the customer; reworded. https://aws.amazon.com/fsx/windows/faqs/
- **q03-036** (keyed option text and its explanation). "Aurora Serverless v2" is now named "Aurora serverless" throughout the Aurora User Guide, its document history and the Aurora FAQ. Option renamed; explanation says "Aurora serverless (formerly Aurora Serverless v2)" and adds the pause at zero capacity. https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-serverless-v2.html and https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-serverless-v2.how-it-works.html
